Claude prompt caching and Batch API: what they cost and when they help

Short answer: reading input from the prompt cache costs between 2.5% and 10% of the normal input price, depending on the model. Writing to the cache costs 1.25 times normal input for a 5-minute cache and 2 times for a 1-hour cache. Requests through the Batch API cost half the normal price.

Prompt caching

If many requests start with the same long prefix, such as instructions, tool definitions or shared documents, that prefix can be cached. For example, a 20,000-token prefix sent 10,000 times a day on Opus 5.5 is 200 million input tokens: about $800 a day at the normal input price, and about $40 a day if every request after the first reads it from cache, plus the cost of writing the cache. Real hit rates are lower when the prefix changes or the cache expires, so check your own share.

Batch API

Batch requests are processed asynchronously within 24 hours at half price. Work that nobody waits for, such as evals, backfills and nightly jobs, is the natural fit.

Questions

How much does prompt caching save on Claude?

A cache read costs 2.5% to 10% of the normal input price depending on the model, while cache writes cost 1.25 times (5-minute) or 2 times (1-hour) normal input. The saving depends on how much of each request repeats and how often the cache is hit.

How much cheaper is the Claude Batch API?

Batch requests cost 50% of the normal price, in exchange for asynchronous processing within 24 hours.

How do I know if I use caching or batch?

Open your usage CSV in the free checkup at aispenddoctor.com. It reports cache share and batch share when the file contains that data, and marks them as not available when it does not.
